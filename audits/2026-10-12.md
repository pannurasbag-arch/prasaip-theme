## Issues and proposed fixes

### 1. Site backups and error log still download publicly. Priority: high, security

Flagged on 5 October and approved for deletion then. They are still there today. Live HEAD requests on .com return 200:

- https://www.prasaip.com/prasaip.zip (198,431,024 bytes, application/zip)
- https://www.prasaip.com/prasaip15_10_2024.zip (97,359,753 bytes, application/zip)
- https://www.prasaip.com/error_log (42,253 bytes)

The Hostinger connector file listing of the .com web root confirms all three files. It also shows `.htaccess.bk` (261 bytes), which is probably an old copy of .htaccess. The same paths return 404 on .in.

Proposed fix:
1. Delete the three files, and `.htaccess.bk`, in Hostinger File Manager. The connector has no delete operation, so the owner must do this.
2. Then change the database password (update wp-config.php to match) and regenerate the WordPress salts. The backups likely contain wp-config.php and a database dump, and they have been public for at least a week.
3. Optional, after deletion: add a rule to .htaccess that denies `*.zip`, `*.sql` and `error_log` in the web root, so a future backup cannot be served.
